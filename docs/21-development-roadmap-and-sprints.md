## 0. الافتراضات

الجدول أدناه **مشروط بهذه الافتراضات**. أي تغيير فيها يغيّر المدة.

| الافتراض | القيمة |
|---|---|
| طول السبرنت | أسبوعان |
| الفريق | 2 باك إند · 1–2 فلاتر · 1 ويب/بليد · 1 QA · تصميم بالحاجة |
| التصميم | التوكنز والشاشات القائمة جاهزة — **الشاشات الناقصة (§0.2) تُصمَّم قبل سبرنتها** |
| القرارات | 23 قرار محسوم؛ الباقي يُحسم قبل سبرنته |

### 0.1 قاعدة التوازي — العقد أولاً

> الباك إند يسبق الموبايل بسبرنت واحد **في العقد لا في التنفيذ**.

في بداية كل سبرنت يُكتب `contracts/openapi.yaml` للميزة **أولاً** ويُراجعه الفريقان. ثم:
- الباك إند يبني التنفيذ
- الموبايل والويب يبنيان مقابل **خادم وهمي مولّد من العقد**

فلا ينتظر أحد أحداً، وانحراف السكيما يفشل في CI.

### 0.2 شاشات يجب تصميمها قبل سبرنتها

| الشاشة | السبرنت |
|---|---|
| كل حالات الخطأ والتحميل والأوفلاين (**غير موجودة إطلاقاً**) | 1 — عابرة للمنتج |
| رفض إذن الموقع | 4 |
| منتقي الموقع على الخريطة (D-11) | 3 |
| مرفقات المحادثة + موقع المقابلة (D-18) | 6 |
| الاشتراك والدفع والتجديد (D-01) | 7 |
| تقديم بلاغ (**لا واجهة له إطلاقاً**) | 8 |
| تخطيطات الجوال للويب (D-37) | 9 |

## سبرنت 0 — الأساس

**الهدف:** أول commit ينتج بيئة تعمل وتُنشَر آلياً.

| المسار | المهام |
|---|---|
| Backend | مونوريبو · Laravel 12 · Postgres+PostGIS · Redis · Docker · القواعد الأربع كهيكل مجلدات · `ApiResponse` trait · معالج الاستثناءات المركزي · Sanctum · Pint + Larastan L6 + Pest |
| Mobile | مشروع Flutter بـ FVM · هيكل `CLAUDE_TEMPLATE` · `ApiConsumer` + interceptors · `service_locator` · `go_router` · ديزاين سيستم (`AppColors`/`AppTextStyles`/`AppDimensions` من `HANDOVER §4`) · ARB |
| Web | Blade + Tailwind بتوكنز مشتركة · مكوّنات `ui/` الأساسية |
| DevOps | CI بمرشّحات مسار · بيئتا dev و staging · إدارة الأسرار |
| Docs | `contracts/openapi.yaml` هيكلياً · `CLAUDE.md` للجذر |

**معيار الخروج:** endpoint `/health` يمر عبر Controller→Service→Repository ويعيد الغلاف الموحّد · التطبيق يبني على المنصتين · CI أخضر · **اختبار معماري يفشل عند وجود استعلام في Service**.

> **مهمة مميزة:** اكتب اختبار Pest يفحص أن أي كلاس في `App\Services` لا يستورد `Illuminate\Database`. القواعد التي لا تُفرض آلياً تُخالَف خلال شهر.

## طريقة العمل

1. **العقد أولاً** — `openapi.yaml` يُكتب ويُراجع قبل أي كود في كل ميزة
2. **فرع لكل مهمة** من `develop` · `feat(api/jobs):` · PR بمراجع واحد على الأقل
3. **CI يحجب الدمج** — Pint · Larastan L6 · Pest · `flutter analyze` · `flutter test`
4. **اختبارات معمارية تفرض القواعد الأربع** — لا مراجعة بشرية تعتمد عليها
5. **عرض في نهاية كل سبرنت** على بيئة staging بمعايير الخروج
6. **سجل القرارات يُحدَّث** فور حسم أي قرار — والمستندات تتبع الكود في نفس الـ PR
